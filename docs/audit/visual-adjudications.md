# 配图复核 · 实测裁定表（mit-6.5840）

**这张表做什么**：`check_reviewed.py` 读它，把「已被实测证伪的复核结论」从阻塞列表里移出。
**规则见 `courselingo/docs/quality-audit.md` 附录八 / 附录十一 / 附录十二。**

## 写入规矩

| 列 | 要求 |
| --- | --- |
| 图 | 图名（本轮用的是复核报告的文件名里的 stem） |
| 原判定 | 复核报告的结论 |
| 裁定 | 只认 `可用` |
| 依据（实测值） | **必须含数字**，且**必须粘属性原文或量到的值** |
| 裁定人 | 谁裁的 |
| 针对报告 | **那份复核报告的 SHA256 前 16 位**（归一化后） |

**★ 为什么必须钉报告哈希**：裁定是「**对某一次判定的反驳**」，不是「对这张图的永久结论」。
报告比裁定新 ⇒ **裁定不适用**，按新报告处置。
（实测教训：我先用 mtime 判，本地过、CI 红 —— **干净检出里 git 把所有文件 mtime 设成同一时刻，同仓内比 mtime 无意义**。）

**★ 为什么依据必须粘原文**：否则「**我读了属性**」和「**我目测了**」在记录里**长得一模一样**。

## ★★ 最重要的一条：**裁定是「图级」的，不是「主张级」的**

**`check_reviewed.py` 的粒度是图名** —— 它读到的阻塞项形如 `intro-8:需小修`，**一张图只有一条**。
**⇒ 因此写一行 `可用`，等于把**这张图报告里的全部主张**一起移出阻塞列表。**

**⇒ 铁律：只有当「这份报告的结论**整体**不成立」时才写 `可用`。
若报告里同时有成立的主张（哪怕只有一条），不得写裁定 —— 去改图。**

**而我违反过它（2026-09-29，`intro-8`）**：那张图的报告有三条 ——

| # | 报告的主张 | 实情 |
| --- | --- | --- |
| ① | 虚线说明框与粉色段无连线、指代错位 | **成立，要改** |
| ② | 粉色三段不等长（5–6%） | 不成立（三段都是 122） |
| ③ | 第三行蓝条文字两侧仅约 25px | 不成立（实测 15px） |

**我为了反驳 ②③ 写了两行 `可用` ⇒ ① 被一并压掉，`01-introduction` 一度因此被放行。**
**⇒ 而我上一轮才刚刚写下「裁掉的是它给的数，不是它指的事」—— 这一轮用机制把它抹掉了。**

**⇒ 判据：写裁定之前，先把这份报告的主张**逐条列出来**，问「有哪一条是我承认的」。有 ⇒ 不写裁定。**
